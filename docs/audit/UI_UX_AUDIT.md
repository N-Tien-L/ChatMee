# ChatMee: Frontend UI/UX audit (v0)

Date: 2026-10-11 · Scope: `frontend/app`, `frontend/components` (except `components/ui`), stores and hooks they use.
Method: code reading only. The app was not run and no screenshots were taken, so visual findings (spacing, contrast)
need a check in the browser during CM-063. Tickets refer to `docs/plan/MVP_V0_PLAN.md`; acceptance criteria to SPEC-008.

Severity: **H** breaks a core flow or misleads the user · **M** clearly hurts the experience · **L** polish.

## 1. Summary

The frontend is functionally careful (loading, error and empty states, focus handling, ARIA, optimistic
messages with resend) but it does not feel like one product:

- **Two visual languages.** Login is dark, glassy, animated, with the display fonts Borel and Jersey 10.
  The dashboard is a plain gray/blue Tailwind admin layout. Nothing connects them.
- **The design tokens are not used.** `globals.css` defines shadcn tokens (`--primary`, `--muted`, `--border`, radius...),
  but app components hard-code `gray-*`, `blue-*` and `bg-gradient-to-br from-blue-400 to-purple-500`.
- **The sidebar does not answer "what is new?".** Rooms show capacity and creation date instead of last message,
  time and unread count (fixed functionally by SPEC-008, visually here).
- **Many controls do nothing or lie**: call/video/info/more buttons, fake room settings, "coming soon" text, `href="#"` links.

## 3. Design direction for v0

Keep it fast: no new UI library, no theme switcher. Use what is installed (Tailwind 4, shadcn tokens, lucide, motion).

1. **Tokens first.** Choose one accent (a ChatMee color, for example a teal/indigo) as `--primary`; app components use
   `bg-background`, `text-muted-foreground`, `border-border`, `bg-primary` etc. No raw palette classes outside `components/ui`.
2. **Layout.** Desktop: 320 px sidebar + conversation; optional right panel for room info. Mobile (< 768 px):
   list screen → conversation screen with Back, no drawer.
3. **Shared primitives** (in `components/common/`, not in `components/ui`): `UserAvatar`, `RoomAvatar`, `UnreadBadge`,
   `RelativeTime`, `ConfirmDialog`, `EmptyState`.
4. **Typography.** Geist everywhere; brand font only for the wordmark on login (or none).
5. **Motion.** Subtle: message enter fade, no delays before primary actions.
6. **Accessibility kept.** Existing ARIA, focus return and `role="log"` behaviour must survive the redesign (tests exist).

## 4. Out of scope for v0
Dark mode, landing page, emoji picker, message actions menu (edit/delete are v1), drag-and-drop, notification sounds.
