## Implementation

- New `.github/workflows/e2e-ci.yml`: separate job, `contents: read`, checkout credentials
  not persisted, JDK 17, Node 22, one Chromium worker, Ubuntu 24.04. The pinned Playwright
  runtime explicitly supports Ubuntu 24.04. Existing backend/frontend CI files have no diff.
- Run the exact local command `npm run test:e2e`: target guards, intentional startup
  failure check, then the complete browser suite. CI installs locked dependencies and
  Chromium with Linux OS dependencies, and makes the existing Maven wrapper executable.
- The launcher starts fresh loopback-only Mongo/Redis through the existing test-only
  Java/Testcontainers entry point, synthetic OAuth, real backend and a production frontend
  build. It checks the production artifact before starting Next/proxy. No target overrides,
  real OAuth secrets, shared data services or paid testing service are required.
- Bounded Docker preflight, command completion, HTTP readiness and whole-suite/job timeouts.
  Unix child processes lead newly created process groups; shutdown targets only those groups.
  Windows uses tracked PIDs/trees. Testcontainers hooks/reaper manage their own containers.
  No process-name kill, occupied-port kill, prune, volume command or database deletion.
- Allowlisted JSON diagnostics, updated during startup and after every test. The workflow
  uploads only `startup.json`, `suite.json`, `failure-check.json` on failure, configured
  retention **7 days**. No raw request/response, child output, environment, cookie, browser
  storage, trace, screenshot, video, token or credential is included in these files.
