v0.2 must cover EVERY messaging capability that is missing and that mainstream chat apps (Messenger, WhatsApp, Slack, Telegram) all have.
Produce a complete, executable plan (specs outline, design deltas, ADR list, tickets, lanes, milestones) for the whole version.

## 3. Scope: capabilities to cover
Verify the current state of each item in code first. Mark it Exists / Partial / Missing with file evidence. Plan only what is Partial or Missing.

A. Per-message actions (extend the existing actions menu)
 - Reply with quoted preview + jump to original; Edit own message ("edited" label); Delete for me vs Unsend for everyone (tombstone "message was unsent");
   Forward; Pin/unpin (rooms); Multi-select (lowest priority).
B. Reactions: emoji reactions with counts and who-reacted list, quick-react bar, double-tap/click to heart.
C. Delivery and read state: delivered + seen (per-member `lastReadMessageId`, "Seen by" avatars on last seen message), unread badge accuracy,
   "New messages" divider inside a conversation, mark-as-unread on a room.
D. Content types: image and file attachments (upload, preview, lightbox, download, limits, virus/MIME handling), link preview (SSRF-safe),
   auto-linking, emoji picker, @mentions (with mention notifications), light markdown + code block (XSS-safe). GIF/sticker/voice/location = list as "v0.3 candidates" only, with a one-line reason.
E. Time and layout: relative day labels (Today/Yesterday), absolute time tooltip, long-message "See more", bubble grouping polish.
F. Search and navigation: in-conversation search with highlight and jump-to-message, room media/files/links tab, jump to date.
G. Realtime and reliability: per-room drafts, tab title unread count + sound, Web Push notifications, offline/reconnect banner with gap sync of missed messages,
   per-room mute (wire up existing `participants.isMuted`), cross-instance fan-out status check (Redis pub/sub).
H. Safety and moderation: admin/owner delete of others' messages, kick/ban with rejoin cooldown (AC-009-26), report review minimum viable path,
   rate limits for new write paths (edit, react, upload).
I. Accessibility: keyboard and screen-reader behavior for every new interaction, reduced motion, touch targets, long-press parity with right-click.
