## Behavior delivered

- Capture a confirmed head from the contiguous loaded segment; optimistic messages are excluded.
  Freeze that overlap anchor during disconnection/recovery and retain the original anchor if a
  newer reconnect supersedes unfinished recovery.
- Fetch newest history, then walk existing opaque `before` cursors sequentially to the anchor
  ID or history exhaustion. Empty/failed initial history recovers one newest page and restores
  its ordinary older-page cursor; it does not fetch all history without an anchor.
- Buffer fetched pages while the gap is open. Existing rows and live frames stay visible with
  an explicit incomplete/recovering banner; recovered pages publish together after overlap.
  Merge by server ID and reconcile stored client IDs with pending/lost-echo copies. Equal
  timestamps use the existing Mongo String/ObjectId history tie-break, without decoding cursors.
- Preserve loaded older rows and their existing cursor. Track the visible message ID/offset to
  preserve scroll while recovered and live rows are inserted together, including own saved rows.
  Callback snapshots include same-turn live frames so the completed session cache also keeps them.
- Stop after ten requests per automatic or manually continued round. Continue/Retry resumes the
  saved cursor; repeated cursors terminate with an error instead of an unbounded loop.
- Page/network/5xx errors keep recovery incomplete. 429 honors numeric or HTTP-date Retry-After
  through a guarded retry deadline. Reconnect during cooldown invalidates the older generation
  and requires a new head walk after cooldown; manual Retry cannot bypass it.
- 401 stops recovery and follows the existing API client's expired-session redirect. 403/404
  stop recovery and remove the room through the existing room-store/ended-view behavior.
- Room/account changes, unmount, logout/cache reset and newer reconnect invalidate old responses.
  Cache keys include the account, and stale live/error callbacks and pending timeouts are guarded.
  A superseded unresolved older-page request no longer blocks paging after successful recovery.

## Remaining limits and CM-096 next steps

- Current app-side timestamp/typed-ID ordering remains the contract. An insert committed late
  behind an already-seen anchor or behind a cursor already traversed can escape this walk.
  This is characterized by the late-write test; recovery is not durable or exactly-once replay.
  Multi-instance ordering and replay of edits/deletes/reactions remain outside CM-095.
  A stronger guarantee needs a separate owner-approved spec/ordering amendment (for example
  a commit-order watermark/replay contract); none was introduced here.
- Incomplete history pages/progress stay in the mounted hook. They are not persisted as a
  contiguous reusable cache. Unmount discards that attempt; reopening loads the normal newest
  segment and exposes older navigation. Existing rows/cursor are retained during a mounted
  recovery and stored again after successful completion.
- HTTP-date Retry-After is implemented; automated 429 regressions exercise numeric seconds.
  Scroll tests use deterministic DOM geometry; actual browser/mobile scroll remains subject
